# Data Pipeline

Scripts for ingesting raw course data and building the embeddings used at runtime.
Note: this pipeline does not update database objects for the Critical Review, as these require an authenticated Brown University account.

## Automated refresh

The recommended way to keep data fresh:

```bash
python3 pipeline/refresh_data.py --dry-run       # preview what would change
python3 pipeline/refresh_data.py --apply          # fetch, embed, rebuild
python3 pipeline/refresh_data.py --apply --force-term 202720  # force one term
```

`refresh_data.py` discovers valid CAB terms, fetches only changed data, preserves Critical Review fields, generates missing/stale embeddings, and rebuilds derived files. All freshness state is tracked in `data/manifest.json`.

## Directory layout

### `scrape/` — fetch raw course data from CAB
- `fetch_semester.py` — pull course list for a single srcdb term
- `getCourseDescriptions.py` / `getCoursesFancyNoFail.py` — enrich with descriptions
- `parseCourses.py` — normalise to JSON
- `mergeDescriptions.js` — merge enriched descriptions into overview
- `scrape_concentrations.py` — scrape concentration requirements from the bulletin

### `embed/` — build embeddings and derived data files
- `embed_courses.js` — call OpenAI embeddings API, write `data/embeddings.jsonl`. Detects stale embeddings via text hash in manifest and deduplicates on rebuild.
- `extract-current-courses.js` — derive current/upcoming terms from `data/manifest.json` (falls back to latest terms in `courses_overview.json` if no manifest exists)
- `shard_courses.js` — split courses for distributed embedding (optional)

### `utils/` — shared utilities
- `srcdb.py` — srcdb code parsing, candidate generation, CAB API probing, current term identification
- `manifest.py` — manifest load/save, term checksums, embedding text hashes, Critical Review field preservation

### `benchmark/` — measure retrieval and cluster performance (optional)
- `cloud_benchmark.js` — end-to-end latency on AWS
- `m3_benchmark.js` — distribution layer benchmark
- `run_node.js` — helper to spin up a single cluster node for testing

## Outputs (written to `data/`)
- `courses_overview.json` — full course metadata (~131k sections)
- `embeddings.jsonl` — one 256-dim embedding vector per section, keyed `crn:srcdb`
- `current_courses.json` — unique course codes for current/upcoming semesters
- `manifest.json` — term checksums, embedding text hashes, freshness timestamps
- `idmap.json` — maps FAISS integer IDs → course codes (generated by `scripts/indexer.js`)

## Manual steps

Individual pipeline scripts can still be run standalone:

```bash
python3 pipeline/scrape/fetch_semester.py 202720
node pipeline/embed/embed_courses.js
node pipeline/embed/extract-current-courses.js
```
